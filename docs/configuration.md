# Настройка сервера через интерфейс

Здесь повторяем конфигурацию из README через поля редактора HY2-P. Домен `vpn.example.com` и email `admin@example.com` замените своими.

## Подготовка

- Направьте A-запись домена на публичный IPv4 сервера. Если есть AAAA-запись, IPv6 тоже должен вести на этот сервер. Дождитесь обновления DNS: [проверка адреса и FreeDNS](install.md#бесплатный-домен-freedns).
- Откройте **UDP 8443** для подключений и **TCP 80** для HTTP-проверки ACME в firewall сервера и хостинга. Порт панели открывается отдельно.
- В **Управление HY2** обновите выбранный экземпляр до последней стабильной версии. Создание ключей ECH доступно с 2.12.3.

Откройте **Конфигурация** и выберите нужный экземпляр. Разделы редактора перечислены слева; на телефоне прокрутите меню по горизонтали. Поле можно найти по его имени через **Найти свойство**.

## 1. Параметры подключения

- **Публичный адрес**: ваш домен, например `vpn.example.com`.
- **Публичный UDP-порт**: `8443`.
- **SNI совпадает с адресом**: включите.

## 2. Listen

В поле **listen** укажите `:8443`, с двоеточием в начале. Для этого примера публичный порт и порт прослушивания совпадают.

## 3. TLS / ACME

В списке **Сертификат Hysteria2** выберите **Автоматический сертификат ACME**. Появятся поля:

- **acme.domains**: ваш домен, например `vpn.example.com`. Каждый домен вводится с новой строки, без дефисов.
- **acme.email**: ваш email.
- **acme.ca**: `letsencrypt`.
- **acme.dir**: `/data/acme-hy2`.
- **acme.type**: **По умолчанию**, как в примере.

Для HTTP-проверки входящий TCP 80 должен быть опубликован в Docker и доступен извне. Недоступные для редактирования внутренние порты проверки задаёт панель. Сертификат этого раздела используется экземпляром HY2; HTTPS самой панели настраивается отдельно.

## 4. ECH

1. Заполните **Внешнее имя SNI для ECH**, например `public.example.com`, заменив его выбранным внешним именем. Оно видно снаружи, поэтому не используйте здесь основной домен подключения, который хотите скрыть.
2. Нажмите **Создать**.
3. Убедитесь, что **ech.keyPath** заполнился автоматически. Это путь к созданному ключу; вводить путь из примера не нужно.

ACME обновляет TLS-сертификат, а ключ ECH создаётся отдельно. Панель добавляет публичный ECH в ссылку подключения; приватный ключ остаётся на сервере. Приложение пользователя должно поддерживать ECH для Hysteria2.

## 5. Obfuscation

- **obfs.type**: `salamander`.
- **obfs.salamander.password**: нажмите **Сгенерировать** рядом с полем или задайте свой случайный пароль.

Не используйте пароль из чужого примера. Для клиентов, добавленных через подписку, панель передаст пароль автоматически.

## 6. QUIC parameters

- **quic.maxIdleTimeout**: `30s`.
- **quic.disablePathMTUDiscovery**: `false`.

## 7. Bandwidth

- **ignoreClientBandwidth**: `true`.
- **bandwidth.up** и **bandwidth.down**: оставьте пустыми.

## 8. Congestion

- **congestion.type**: `bbr`.
- **congestion.bbrProfile**: `standard`.

## 9. Speed Test

В поле **speedTest** выберите `true`.

## 10. UDP

- **disableUDP**: `false`. Это разрешает передачу UDP через VPN.
- **udpIdleTimeout**: `60s`.

## 11. Authentication

В списке **Кто управляет доступом** выберите **Пользователи панели**. Поля `auth.*` вручную заполнять не нужно.

## 12. Masquerade

- **masquerade.type**: `proxy`.
- **masquerade.proxy.url**: `https://reuters.com`.
- **masquerade.proxy.rewriteHost**: `true`.

Остальные свойства нового экземпляра оставьте по умолчанию. Если в перечисленных полях уже были другие значения, замените их; чтобы очистить поле, используйте кнопку сброса рядом с его названием. В списках выбирайте именно `true` или `false`, когда они указаны выше.

## Сохранение и подключение

1. Нажмите **Сохранить**.
2. Если панель сообщает о несовпадении опубликованного UDP-порта, нажмите **Применить** в блоке публикации порта. Это доступно для управляемой Docker-установки. Дождитесь результата проверки; при необходимости войдите в панель заново.
3. При первом включении ACME в управляемой Docker-установке откройте **Настройки → Обслуживание → Перезапустить панель** и подтвердите действие. Перезапуск применит публикацию HTTP-порта проверки сертификата.
4. Вернитесь к выбранному экземпляру и нажмите **Запустить** или **Перезапустить**. В **Управление HY2** проверьте его состояние и журнал выпуска сертификата.
5. В разделе **Пользователи** нажмите **Добавить**, создайте пользователя и разрешите ему этот экземпляр.
6. Откройте подключение пользователя и отсканируйте QR-код либо добавьте адрес подписки в приложение. После смены пароля или ключа ECH обновите подписку.

## Для чего нужен ECH

ECH скрывает настоящее имя сервера в TLS и помогает минимизировать риск блокировок по SNI. Это дополнительная защита, но не 100% гарантия доступности: IP сервера остаётся видимым и может быть заблокирован отдельно.

Подробнее: [ECH в Hysteria2](https://v2.hysteria.network/docs/advanced/ECH/) и [ограничения ECH в RFC 9849](https://www.rfc-editor.org/rfc/rfc9849.html#section-1).
