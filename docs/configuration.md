# Как настроить пример из README

Этот конфиг используется с HY2-P. Понадобятся домен, доступ к настройкам DNS и приложение с поддержкой Hysteria2, Salamander и ECH.

## Подготовка

- Направьте A-запись домена на публичный IPv4 сервера. Если есть AAAA-запись, IPv6 тоже должен вести на этот сервер. Дождитесь обновления DNS: [проверка адреса и FreeDNS](install.md#бесплатный-домен-freedns).
- Разрешите **UDP 8443** для подключений и **TCP 80** для HTTP-проверки ACME в firewall сервера и хостинга. В Docker опубликуйте эти порты; для установленной панели используйте **Применить UDP-порт** и настройку порта проверки ACME.
- Обновите выбранный экземпляр HY2 до последней стабильной версии. Встроенное создание ключей ECH доступно с 2.12.3.

## Настройка в панели

1. В **Конфигурация → ECH** заполните **Внешнее имя SNI для ECH** и нажмите **Создать**. Скопируйте полученный `ech.keyPath`: файл ключа должен существовать до запуска экземпляра.
2. Откройте редактор YAML и вставьте пример из README. Замените `vpn.example.com`, `admin@example.com` и пароль Salamander. Вместо `/data/ech/REPLACE_WITH_KEY_DIRECTORY/ech.pem` укажите путь из предыдущего шага.
3. В **Параметрах подключения** задайте свой домен, UDP-порт `8443` и включите **SNI совпадает с адресом**. В **Authentication** выберите **Пользователи панели**: параметры аутентификации панель добавляет сама.
4. Сохраните конфигурацию. Если меняли UDP-порт, нажмите **Применить UDP-порт**. Запустите или перезапустите экземпляр, проверьте выпуск сертификата ACME в журнале.
5. Добавьте пользователя, разрешите ему этот экземпляр и импортируйте подписку в приложение. После смены ключа ECH или пароля обновите подписку. Пароль Salamander на сервере и клиенте должен совпадать; панель передаёт его и публичный ECH в ссылке подключения.

ACME выпускает и продлевает TLS-сертификат, а ключ ECH создаётся отдельно. В подписку попадает только публичная конфигурация ECH; приватный файл остаётся на сервере.

## Для чего нужен ECH

ECH скрывает настоящее имя сервера в TLS и помогает минимизировать риск блокировок по SNI. Это дополнительная защита, но не 100% гарантия доступности: IP сервера остаётся видимым и может быть заблокирован отдельно.

Подробнее: [ECH в Hysteria2](https://v2.hysteria.network/docs/advanced/ECH/) и [ограничения ECH в RFC 9849](https://www.rfc-editor.org/rfc/rfc9849.html#section-1).
