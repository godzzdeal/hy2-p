# Управление установкой

Команда hy2-panel устанавливается в /usr/local/bin. Все операции выполняются с sudo.
Путь по умолчанию — /opt/hy2-panel; другой можно выбрать через --directory при установке.
Менеджер работает с локальным Docker Engine и отдельным проектом Compose hy2-panel.

## Команды

- status — состояние контейнера и установленный коммит.
- logs — журнал панели; Ctrl+C завершает просмотр.
- start, stop, restart — управление панелью и её ядром.
- url — адрес или команда SSH-туннеля.
- backup — согласованная копия данных, .env и внешних сертификатов.
- update [версия] — обновление панели; по умолчанию последний стабильный релиз.
- rollback [--yes] — возврат версии и данных из копии перед обновлением.

Длительные изменяющие операции защищены блокировкой. Просмотр журнала не блокирует обновление.
Текущие данные, исходники и ключи не включаются в публичные Git-коммиты установщиком.

## Обновление

Новая версия скачивается в releases/<SHA> и получает отдельный Docker-образ.
Сервер скачивает готовый образ своей архитектуры из GitHub Release, проверяет SHA-256 и загружает в Docker. Текущий контейнер продолжает работать во время скачивания. Перед переключением он останавливается,
чтобы SQLite, конфигурация, счётчики и ключи попали в согласованную копию.
Проверка нового контейнера использует внутренний HTTP endpoint и состояние Docker healthcheck.

При ошибке возвращаются прежний образ и резервная копия данных. Предыдущие образы не удаляются.
Если процесс был прерван, следующая изменяющая команда сначала обработает update.pending.
Не удаляйте этот файл или указанную в нём копию до завершения восстановления.
Если обе версии не запускаются, копии и журнал сохраняются для ручного разбора.

Для перехода с v0.1.3 и старше скачайте install.sh из последнего релиза и повторно запустите его через sudo bash с --yes. Новый установщик обновляет существующую установку без сборки, сохраняя данные и параметры. Старый hy2-panel update ещё использует сборку. После перехода обычный update скачивает готовые образы.
Ветка main и коммиты без релизных образов требуют явного HY2_BUILD_FROM_SOURCE=true (режим разработки).

## Ручной откат

rollback возвращает не только код, но и данные на момент копии перед обновлением.
Изменения после того момента сохраняются в отдельной страховочной копии перед откатом.
Команда показывает путь копии и запрашивает подтверждение; --yes пропускает вопрос.
После успешного отката сбойная версия не становится кандидатом следующего отката.

## Копии и восстановление

Копии находятся в backups/<UTC-время>.<случайный суффикс>:

- data.tar.gz — весь том /data, включая базу, ключ шифрования, сертификаты и ядра.
- certs.tar.gz — внешняя папка сертификатов.
- environment — начальные параметры .env.
- manifest.json — версия и время создания.

Папки копий имеют права 0700, файлы — 0600. Они не удаляются автоматически.
Для аварийного восстановления на другом сервере нужны все файлы копии и образ/исходники её версии.
Универсальная команда импорта чужой копии пока не предусмотрена; не подменяйте том работающего контейнера.
Копирование одного panel.db без ключа users.key не восстанавливает пользователей.

## UDP-порт из панели

Сохраните публичный UDP-порт и listen в «Конфигурации», затем нажмите «Применить UDP-порт». Сначала запустите ядро; остальные изменения его конфигурации примените перезапуском ядра. Поддерживается один UDP-порт и listen без фиксированного IP.
Помощник меняет только две переменные UDP, пересоздаёт панель, проверяет проброс, локальный UDP-ответ со случайным кодом и стабильность ядра. Если проверка не проходит, возвращает прежние порты и запускает ядро на прежнем порту. Ссылки используют действующий порт. Сохранённый желаемый порт остаётся для повторной попытки.
Статус проверки сохраняется при перезагрузке страницы; после пересоздания войдите заново. Транзакция защищена общей блокировкой; прерванный запуск восстанавливается при старте помощника. Если восстановление не удалось, проверьте docker compose logs port-agent с теми же файлами Compose и окружением установки.
Firewall сервера, firewall хостинга и мобильная сеть проверяются отдельно. Помощник не изменяет их правила.

Помощник работает отдельным root-контейнером с Docker socket и доступом к папке установки. Его единственный изменяющий запрос принимает два числовых порта; произвольные команды и пути не принимаются. Веб-панель работает под UID 10001 без Docker socket и общается с помощником через локальный Unix socket. Не подключайте compose.managed.yaml к ручной установке: используйте установщик.

## Порт веб-панели и HTTPS

Сохраните изменения в веб-панели и выполните sudo hy2-panel restart.
Менеджер прочитает сохранённый порт и настройки HTTP challenge панели и ядра, обновит .env и пересоздаст контейнер.
Панель и ядро используют один внешний TCP 80. Внутренний HTTP challenge ядра управляется панелью на loopback:9090.
После перехода с v0.1.0 выполните sudo hy2-panel restart один раз, чтобы обновить публикацию портов.
В Docker выбирайте адрес прослушивания 0.0.0.0; 127.0.0.1 внутри контейнера недоступен через публикацию порта.
Для внешних ключей в certs используйте группу 10001 и права 0640 (папка — 0750).
PANEL_BIND в .env задаёт адрес публикации на самом сервере: 127.0.0.1 для SSH, 0.0.0.0 для публичного доступа.
Перевод на публичный HTTPS требует DNS-записи и доступных TCP-портов панели и HTTP challenge.
