# Firewall и порты

Панель управляет правилами UFW на Ubuntu через отдельный помощник. Правила firewall хостинга меняются в кабинете провайдера. Публикация Docker определяет, какой порт хоста направлен в контейнер.

## Подключить помощник

```bash
sudo hy2-panel firewall-setup
```

Нужны установленный UFW, systemd и работающая панель. Команда копирует помощник из образа, создаёт `hy2-panel-firewall.service`, записывает защищённые SSH-порты и запускает службу. Существующие правила и состояние UFW не меняются.

Если UFW отсутствует, установите его, затем повторите настройку:

```bash
sudo apt-get install ufw
sudo hy2-panel firewall-setup
```

Откройте **Настройки → Firewall** и нажмите **Проверить**. Здесь можно добавлять и удалять входящие правила TCP/UDP. SSH-порты и текущий порт панели защищены от закрытия. Повторный `firewall-setup` обновляет помощник и список защищённых SSH-портов.

## Какие порты нужны

- TCP `9443`: веб-панель по HTTPS с настройками по умолчанию.
- TCP `8080`: публичная веб-панель по HTTP, если выбран этот режим.
- UDP `8443`: основной экземпляр HY2 по умолчанию. Другие экземпляры используют свои публичные UDP-порты.
- TCP `80`: HTTP-проверка ACME для выпуска и продления сертификата.
- TCP `443`: только если экземпляр использует TLS-проверку ACME; не нужен лишь потому, что панель работает по HTTPS на другом порту.
- TCP на публичном порту экземпляра вместе с UDP: при использовании Mimic.
- Ваш TCP-порт SSH: сохраните его для администрирования.

Внутренние порты Traffic Stats, проверки состояния и API не публикуйте. При DNS-проверке ACME входящий порт проверки не нужен. Панель рекомендует порты по сохранённым настройкам и публикации Docker. Доступность из интернета нужно проверить подключением клиента.

## Команды UFW

Посмотреть правила и их номера:

```bash
sudo ufw status numbered
```

Разрешить конкретный порт, например UDP `8443`:

```bash
sudo ufw allow 8443/udp
```

Удалить созданное разрешение:

```bash
sudo ufw delete allow 8443/udp
```

Или удалить правило по номеру из актуального вывода `status numbered`:

```bash
sudo ufw delete НОМЕР_ПРАВИЛА
```

После удаления номера меняются. `ufw reset` удаляет все правила; он не нужен для отмены одного разрешения. Добавление правил не включает UFW. Перед включением UFW отдельно проверьте разрешение своего SSH-порта.

Опубликованные Docker-порты могут обходить обычные правила UFW. Удалённое разрешение UFW не означает, что такой порт закрыт извне. Проверяйте публикацию Docker и firewall хостинга.

## Поменять UDP-порт HY2

В **Конфигурации** выбранного экземпляра задайте публичный UDP-порт и `listen`, сохраните, затем нажмите **Применить** в блоке публикации. Экземпляр не обязательно запускать заранее. Панель проверяет публикацию и при ошибке возвращает прежние порты. Пересоздание контейнера прерывает подключения всех экземпляров.

Проверка подтверждает работу внутри сервера. Затем подключитесь с устройства пользователя, чтобы проверить firewall хостинга и сеть оператора.

## Служебные команды

Эти команды запускает помощник. Для ручного изменения портов используйте форму в панели.

- `apply-udp ОПЕРАЦИЯ ПУБЛИЧНЫЙ_ПОРТ LISTEN_ПОРТ [ID]`: применяет публикацию. ID по умолчанию `default`. Операция содержит 32 шестнадцатеричных символа; требуется совпадающий служебный токен проверки. Коды: `0` при успехе, `10` при возврате прежних портов, `11` при ошибке восстановления.
- `remove-udp ОПЕРАЦИЯ ПУБЛИЧНЫЙ_ПОРТ LISTEN_ПОРТ ID`: удаляет публикацию дополнительного остановленного экземпляра, отмеченного для удаления. Основной экземпляр исключён. Коды завершения те же.
- `recover-udp [ОПЕРАЦИЯ]`: восстанавливает незавершённую смену портов либо проверяет завершённую операцию. Код `0` подтверждает указанную завершённую операцию, `10` означает отсутствие подтверждённого применения или успешный возврат, `11` означает ошибку возврата.

Для дополнительных экземпляров ID состоит из 16 шестнадцатеричных символов. Порты принимаются от `1` до `65535`. Служебные токены `PANEL_UDP_PROBE_*` создаются панелью, в `.env` их вручную не записывают.
