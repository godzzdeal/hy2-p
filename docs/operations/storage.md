# Место на диске и очистка

В **Обзоре** показаны рабочие данные, резервные копии, скачанные версии, архивы отката и образы Docker. Удаление резервных копий не уменьшает размер Docker-образов: это разные файлы.

## Очистить образы

```bash
sudo hy2-panel cleanup-images
```

Команда не принимает параметры. Она сохраняет текущий образ, сжимает предыдущий образ в `image-archives`, проверяет SHA256 и содержимое архива, затем удаляет неиспользуемые старые образы этой установки. Завершённые служебные контейнеры HY2-P тоже удаляются; последние строки журнала обслуживания сохраняются в `last-maintenance.log`.

Если архив предыдущей версии не прошёл проверку, её образ не удаляется. Образы, которые ещё используются контейнерами, сохраняются. Рабочие данные, резервные копии и файлы версий команда не удаляет.

После обновления помощник сам запускает очистку. При необходимости повторите её этой командой. Общая очистка всех образов Docker не выполняется.

## Общие слои

Несколько образов могут использовать одни слои. Поэтому сумма колонок `SIZE` больше места, занятого только уникальными слоями этих образов. Панель учитывает общие слои один раз. Сжатый архив отката занимает дополнительное место и показан отдельно.

После удаления образа Docker освобождает слои, которые больше не нужны ни одному образу или контейнеру. Слои работающих контейнеров и других образов остаются. Дисковый кеш хранилища Docker может освобождаться не сразу.

Проверить размеры средствами Docker:

```bash
sudo docker system df -v
```

Команда ничего не удаляет. Для сравнения смотрите `SHARED SIZE`, `UNIQUE SIZE`, число контейнеров и тип используемого хранилища.

## Что сохранить для отката

Нужны предыдущая версия в `releases`, её образ или проверенный архив, копия из `rollback-backup` и файлы указателей `previous` и `rollback-backup`. Не удаляйте их вручную, если рассчитываете на откат.

Перед сжатием и откатом нужно свободное место: архив создаётся до удаления исходного образа, а при восстановлении образ распаковывается снова. Размер архива зависит от содержимого образа.

Старые резервные копии `cleanup-images` не удаляет. Перед ручным удалением копии проверьте, не ссылается ли на неё `rollback-backup` или незавершённая операция обновления.
