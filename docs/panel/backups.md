# Резервные копии

В **Настройки → Резервные копии** нажмите **Создать бэкап**. Копия включает данные панели, пользователей, конфигурации, ключи, сертификаты и настройки установки. Во время создания панель и подключения кратковременно перезапускаются.

Копии сохраняются на сервере в `/opt/hy2-panel/backups`. Результат задачи показывается в уведомлении. Через терминал:

```bash
sudo hy2-panel backup
```

## Облачные хранилища

Можно подключить несколько хранилищ: Яндекс Диск, Google Drive, Dropbox, OneDrive, S3 и WebDAV. Для остальных сервисов есть импорт конфигурации rclone.

1. В разделе **Облачные хранилища** нажмите **Подключить**.
2. Выберите сервис, укажите название и папку.
3. Для облачного диска нажмите **Войти в аккаунт** и разрешите доступ в открывшемся окне. Для S3 или WebDAV введите реквизиты хранилища и нажмите **Сохранить**.
4. У нужного подключения нажмите **Проверить**. Проверка создаёт папку, если её ещё нет, и проверяет доступ к её содержимому. Панель и экземпляры продолжают работать.
5. Нажмите **Отправить бэкап**. Панель создаст свежую локальную копию, загрузит архив и скачает его для проверки содержимого.

Вход в Яндекс Диск, Google Drive, Dropbox и OneDrive работает через OAuth-приложение, зарегистрированное для адреса вашей панели. Его данные вводятся один раз в **Настройки входа**. Скопируйте **Адрес возврата** кнопкой рядом с полем и вставьте в настройках приложения у провайдера. [Настройка провайдеров](cloud-sign-in.md).

Панель получает и обновляет токены прямо с вашего сервера. Демоверсия и сайт HY2-P в этом не участвуют. Установка rclone на компьютер для этих подключений не нужна.

### Другие сервисы

Выберите **Другое (rclone)**, загрузите `.conf` и укажите путь, например `disk:HY2-P`. Если конфигурации ещё нет, её можно создать через [rclone](https://rclone.org/install/):

```bash
rclone config
rclone config file
```

Первая команда создаёт подключение, вторая показывает путь к файлу конфигурации.

В имени архива указаны сервер, время UTC и отпечаток. Локальная копия сохраняется при успешной отправке и при ошибке. Файлы, уже находящиеся на диске, не удаляются. Для восстановления скачайте архив из облака. Внутри находятся данные, сертификаты и параметры установки. Автоматического восстановления из него пока нет; порядок работы с копиями описан в [документации](../operations/backups.md#восстановление).

Данные доступа хранятся в закрытом каталоге на сервере. Пароли и OAuth-токены не возвращаются в браузер. Сам архив содержит секреты сервера: используйте закрытую папку облачного диска. Для шифрования на стороне клиента настройте [rclone crypt](https://rclone.org/crypt/) и укажите его подключение.

При первой проверке или отправке загружается официальный образ rclone; для обычных локальных копий он не нужен. Для работы нужны исходящие HTTPS-соединения сервера с облаком и реестром образов. Автоматического расписания пока нет. Запускайте отправку вручную.

**Отключить** удаляет локальные данные доступа к выбранному аккаунту. Файлы в облаке сохраняются. Разрешение приложения можно отдельно отозвать в аккаунте провайдера. Настройки самого OAuth-приложения сохраняются для других подключений.

Через терминал после подключения хранилища в панели:

```bash
sudo hy2-panel backup-cloud
```

Если подключено несколько хранилищ, укажите ID из карточки подключения:

```bash
sudo hy2-panel check-cloud STORAGE_ID
sudo hy2-panel backup-cloud STORAGE_ID
```

`check-cloud` проверяет доступ без перезапуска панели. `backup-cloud` создаёт новую копию и отправляет её только в выбранное хранилище.
