# Вход в облачные хранилища

Один раз зарегистрируйте OAuth-приложение у каждого нужного сервиса и сохраните его данные в панели. На сервере используйте HTTPS; для локальной проверки подходит HTTP на localhost. Разрешите доступ к диску на странице провайдера. Пароль облачного аккаунта панель не получает.

Откройте **Настройки → Резервные копии → Подключить**, выберите сервис и разверните **Настройки входа**. Скопируйте **Адрес возврата**. Укажите его в настройках OAuth-приложения провайдера без изменений, включая порт и путь.

В панели заполните **Client ID** и **Client Secret**, нажмите **Сохранить**. После этого заполните название хранилища, папку и нажмите **Войти в аккаунт**.

## Яндекс Диск

Откройте [Яндекс OAuth](https://oauth.yandex.ru/). Создайте приложение **Для авторизации пользователей**, выберите платформу **Веб-сервисы** и добавьте адрес возврата из панели. Укажите право `cloud_api:disk.app_folder`. Скопируйте Client ID и Client Secret со страницы приложения. Архивы будут храниться в папке приложения на Диске.

Тип **Для доступа к API** использует фиксированный адрес возврата и для этого способа входа не подходит. У существующего приложения проверьте, что его Redirect URI можно менять.

[Документация Яндекса](https://yandex.ru/dev/id/doc/ru/register-auth).

## Google Drive

В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) включите Google Drive API и создайте OAuth-клиент типа **Web application**. Добавьте адрес в **Authorized redirect URIs**. Настройте экран согласия и доступ к приложению для нужных аккаунтов.

Панель запрашивает `drive.file`: доступ к файлам, созданным этим приложением. Если приложение оставлено в режиме тестирования, Google ограничивает срок действия доступа; для постоянных бэкапов настройте публикацию приложения по правилам Google.

[Документация Google](https://developers.google.com/identity/protocols/oauth2/web-server).

## Dropbox

В [Dropbox App Console](https://www.dropbox.com/developers/apps) создайте приложение с доступом **App folder**. Добавьте адрес возврата в **OAuth 2 → Redirect URIs**. Разрешите `files.content.write`, `files.content.read` и `files.metadata.read`.

Скопируйте **App key** в поле **Client ID**, а **App secret** в **Client Secret**. Для аккаунтов вне списка разработчиков может потребоваться одобрение приложения Dropbox.

[Документация Dropbox](https://developers.dropbox.com/oauth-guide).

## OneDrive

Зарегистрируйте веб-приложение в [Microsoft Entra](https://entra.microsoft.com/) с нужным типом аккаунтов: рабочие, личные или оба. В платформе **Web** добавьте адрес возврата, создайте Client Secret. Используйте значение секрета, а не его ID.

Нужны делегированные разрешения Microsoft Graph `Files.ReadWrite` и `offline_access`. Организация может требовать согласие администратора.

[Документация Microsoft](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow).

## Хранение доступа

Ключи приложений и токены хранятся только на сервере в закрытом каталоге установки. В браузере видны статус, название и папка. Сохранённые секреты и токены туда не передаются. При отправке панель обновляет доступ напрямую у провайдера.

Если изменился адрес панели, обновите адрес возврата и настройки входа. Смена Client ID требует повторного подключения аккаунтов. Пустое поле Client Secret при сохранении оставляет прежний секрет, если Client ID не изменился.

Настройки облачных подключений находятся отдельно от данных пользователей и сертификатов. При переносе панели их нужно подключить заново.
